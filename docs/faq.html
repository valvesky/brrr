Troubleshooting

What the icon is telling you, and the cases where brrr is working and still changes nothing.

The mode did not change

Windows, and I am not on the Balanced plan

Best performance is a Power mode on the Balanced plan only. On High performance or Ultimate performance, brrr leaves the plan alone because it is already fast. On another plan it switches to the High performance plan if that plan exists, and otherwise does nothing. See Windows behaviour.

The icon says the performance profile isn’t available

The system refused the switch, or this machine has no performance mode (some laptops and many virtual machines). brrr will not keep asking until every matching process has exited. The log line is performance hold rejected: followed by the reason. On Windows that reason can be “No performance power mode is available on this power plan” or “This version of Windows has no power mode setting”.

The icon says it is paused after a manual change

You (or another tool) moved the mode while a watched program was running. brrr will not fight that. It boosts again the next time, after those processes have exited.

Automatic boost is off, or the config file has an error

“Automatic boost is off” means enabled is false. Turn the switch back on or run brrr --enable. “The configuration file has an error” means config.json does not parse. brrr is watching nothing until you fix the file by hand. Menu edits are refused on purpose. Paths are in config.

My game, zip, or export never triggers it

Only names in the list count, and the defaults are compilers. Add the process name with Add command… or brrr --add. It has to be 1–15 bytes. On Windows, omit .exe. On Linux and macOS the case has to match. A name longer than 15 bytes cannot be added at all. A process that exits in a fraction of a second can also come and go between checks. See adding apps and short-lived processes.

macOS says there is nothing to do

If Low Power Mode is already off and the Mac has no High Power Mode (or it is already on), brrr has nothing to change. Until you enter the password, the status line says “Allow brrr to switch power modes from its menu” and the menu offers Allow Power Mode Switching….

Linux has no power profile service

The tray says “No power profile service” when power-profiles-daemon (or tuned-ppd) is not available. The Omarchy widget says “Waiting for power-profiles-daemon”. Install and start one of them. powerprofilesctl is the quick check. The tray can be up before the daemon is.

There is no tray icon on Linux

brrr does not draw its own panel. A StatusNotifierItem host has to be running: KDE Plasma, waybar, Xfce, the Omarchy shell, or GNOME with the AppIndicator extension. Without one of those, use the systemd user service. You started the tray with brrr --tray or brrr --install; running brrr with no arguments is headless on Linux.

Crashes, a second copy, logs

brrr quit in the middle of a boost

On Linux the daemon drops the hold when the process exits, so the profile does not stay boosted because of a crash. On Windows and macOS the setting would otherwise stick. The next start reads windows-power-restore.json or macos-power-restore.json and restores it only if the mode is still the one brrr set.

“Another brrr instance is already running”

Only one runs per user. The second waits about five seconds and exits with status 75. Quit the tray icon, or stop the systemd service or the Omarchy plugin, before starting another. The widget shows this as another instance running.

Where are the logs?

brrr logs to stderr: process detection, boost requests and results, power-service changes, and manual releases. Quiet scans print nothing; a scan that repairs a mismatch does.

On Windows and macOS the icon has no console. Quit it and run the program from a terminal: brrr --tray, or /Applications/brrr.app/Contents/MacOS/brrr.

Under Omarchy the lines are in the shell journal. A systemd user service logs to its own unit:

journalctl --user -t omarchy-shell -b -f
journalctl --user -u brrr -b -f

On Linux, per-process tracing (process ids, matching names, event source, whether a pidfd was available — not command-line arguments) is:

G_MESSAGES_DEBUG=brrr brrr

Stop the running copy first. all instead of brrr also turns it on. It is noisy during a build. Leave it off for normal use. Stream-loss notices are limited to one every five seconds.

A detected command with no boost request means the boost is suppressed or the power service is unavailable. A request with no result means trouble talking to that service. suppressed:true in the supervised JSON is the manual-change pause. rejected:true is a refused performance mode.

macOS will not open the app

It is not notarized. Right-click the app, choose Open, then Open again, or allow it in System Settings › Privacy & Security. After that, Allow Power Mode Switching… is a separate password prompt for the sudoers rule.

Does this need an administrator?

No, on Windows and Linux. The Windows installer is per-user. On macOS, one password installs a sudoers rule that allows only the four pmset commands listed on the install page. Uninstall asks for that password again to delete the rule.

Will this make compiles, games, or exports faster by some amount?

brrr does not measure that. It switches the operating system’s own performance mode and switches it back. How much that changes a particular machine is up to the firmware, the power plan, and whether you were already in that mode.

I used the old Omapower setup script

brrr was formerly Omapower. The Omarchy plugin retires that old user service once, and only when ~/.config/systemd/user/omapower.service starts the binary that setup.sh installed under ~/.local/share/omapower. It then removes the unit and that directory. Your command list is not part of that directory, so it stays. A service you wrote yourself is not touched.
