Uninstall

Removing the program does not remove your command list. The config directory stays, so a later install picks up the same names.

Windows

Uninstall brrr from Settings › Apps. The uninstaller asks the running copy to quit first, so it can put the power mode back, and it removes the sign-in entry. Your command list stays in %APPDATA%\brrr (or under XDG_CONFIG_HOME if that variable is set).

If you used the portable .exe instead of the installer: turn off Start at login, choose Quit, and delete the file.

Linux

The tray login item:

brrr --uninstall

That removes the autostart entry and the icon it installed. Then delete the brrr binary you placed on PATH.

A systemd user service:

systemctl --user disable --now brrr
rm ~/.config/systemd/user/brrr.service
systemctl --user daemon-reload

Quit a running tray with Quit in its menu so a hold is released cleanly. On Linux the daemon also drops the hold if the process simply exits.

macOS

brrr --uninstall removes both the LaunchAgent (~/Library/LaunchAgents/com.brrr.agent.plist) and the sudoers rule (/etc/sudoers.d/brrr). Removing the rule asks for your password again. Then delete brrr from Applications.

Dragging the app to the Trash on its own leaves the login item and the sudoers rule behind. Run --uninstall first. Start at Login in the menu only toggles the LaunchAgent; it does not remove the sudoers rule.

Omarchy

omarchy plugin remove raw.brrr

brrr stops with the plugin. The configuration file is outside the plugin directory and is kept.

What is left on disk

  • config.json, in the per-system config directory.
  • On Windows or macOS, a restore file in that same directory if a boost was still in progress. The next start of brrr consumes it. If you are not reinstalling, you can delete windows-power-restore.json or macos-power-restore.json after you have checked the power mode yourself. Deleting it does not change the mode; it only forgets the undo record.
