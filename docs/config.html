Config file

One JSON file. The tray, the widget, and brrr --add all edit the same place.

Where it is

SystemPath
Linux~/.config/brrr/config.json
macOS~/Library/Application Support/brrr/config.json
Windows%APPDATA%\brrr\config.json

If XDG_CONFIG_HOME is set and not empty, every system uses $XDG_CONFIG_HOME/brrr/config.json instead, including Windows and macOS.

The menu item Open configuration file (or Open Configuration File on Linux and macOS) opens this file. If it does not exist yet, brrr writes one from the current list first.

The format

{"commands": ["cargo", "rustc"], "enabled": true}
  • commands is an array of process-name strings. Duplicates collapse. See the name rules: 1–15 bytes, no slashes, newlines, or NULs.
  • enabled is optional and defaults to true. The tray switch writes it. false means automatic boost is off; the command list stays.

A missing file means the default compilers, with boost on. An existing file is never replaced by those defaults. {"commands": []} watches nothing, and {"commands": [], "enabled": false} stays that way.

When brrr itself rewrites the file, it writes commands as a sorted array, then enabled if it is changing that, then every other member exactly as it was written. Extra fields are kept, including numbers written out in full, so another tool can share the file. brrr does not lock other editors out. It does follow a symlinked config.json and edits the target.

The file has to be a JSON object. Comments, trailing commas, and trailing junk are rejected.

When the file is broken

While config.json is invalid, brrr watches nothing and releases any boost it holds. The icon says “The configuration file has an error”. Menu edits and brrr --add are refused, so a bad file is not overwritten. Fix it by hand. brrr picks the correction up without a restart.

Valid edits are noticed without polling: the file’s directory is watched, and a short burst of saves is applied together.

Files next to it

You do not edit these. They are how Windows and macOS remember a mode to put back if brrr exits suddenly. They live in the same directory as config.json.

  • Windows: windows-power-restore.json
  • macOS: macos-power-restore.json

Linux does not need one. A power-profiles-daemon hold belongs to brrr’s connection and is dropped when the process exits. Details are in behaviour.

Uninstalling brrr does not delete this directory. Your command list remains.
