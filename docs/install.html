Install

Four ways in. Downloads come from the latest GitHub release.

  • Windows
  • Linux
  • macOS

Windows 10 and 11

Supported from Windows 10 version 1809 onward, and on Windows 11, on x64 and ARM PCs. brrr changes Power mode. That does not need an administrator account, and neither does the installer.

  1. Download brrr-windows-setup.exe and run it. One file covers both architectures and installs the matching program.
  2. It installs for your account only, under %LOCALAPPDATA%\Programs\brrr, and adds a Start menu shortcut.
  3. Unless you untick it, brrr starts when you sign in. Start at login in the icon menu, or brrr --install, changes that later.
  4. The icon sits in the notification area. Windows may hide it in the overflow; drag it onto the taskbar if you do not see it. The icon follows the taskbar’s light or dark theme and shows the current mode.

Prefer no installer? Download brrr-windows-x86_64.exe or brrr-windows-aarch64.exe, put it somewhere it can stay, and run it. Use Start at login or brrr --install so it comes back at sign-in.

On the usual Balanced plan, a watched program switches Power mode to Best performance — the same setting as Settings › System › Power & battery. See what happens on other plans.

Linux

brrr needs power-profiles-daemon, or tuned-ppd, which provides the same interface. Most desktop distributions already include one of them. powerprofilesctl tells you whether it is running. You do not need root or extra capabilities.

The release binary is statically linked, so the same file runs on any distribution.

  1. Download brrr-linux-x86_64.tar.gz or brrr-linux-aarch64.tar.gz.
  2. Unpack it and put the brrr binary on your PATH.
  3. Start the tray now, and at every login:
brrr --install   # tray icon at every login, and its app icon
brrr --tray &    # and right now

The tray icon is a StatusNotifierItem. KDE Plasma, waybar, Xfce, the Omarchy shell, and GNOME with the AppIndicator extension all show it, drawn and themed by the desktop. The menu has the switch, the watched commands, and Add Command…. That asks with zenity, kdialog, or qarma when one is installed, and otherwise opens the configuration file. brrr --uninstall removes the login item.

Without a tray

Run it as a systemd user service. With no arguments, brrr stays headless, which is what a service wants. Create ~/.config/systemd/user/brrr.service:

[Unit]
Description=brrr process-based power profile holds
After=graphical-session.target

[Service]
ExecStart=/absolute/path/to/brrr
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
systemctl --user daemon-reload
systemctl --user enable --now brrr

To stop, see uninstall.

macOS 12 or later

Download brrr-macos.dmg, open it, and drag brrr to Applications. Open it from there. The app is universal: one download for Apple silicon and Intel. It runs as a menu bar icon and does not show a Dock icon.

The app is not notarized. The first time, macOS asks you to confirm it: right-click brrr, choose Open, then Open again. You can also allow it under System Settings › Privacy & Security.

macOS has no power setting an ordinary app can change. Low Power Mode and High Power Mode are switched with pmset, which needs root. Choose Allow Power Mode Switching… from the menu bar icon and enter your password once. brrr installs a sudoers rule, /etc/sudoers.d/brrr, that allows only these commands, for your user only:

/usr/bin/pmset -b lowpowermode [01], /usr/bin/pmset -c lowpowermode [01],
/usr/bin/pmset -b powermode [012],   /usr/bin/pmset -c powermode [012]

Start at Login, or brrr --install (which also installs the rule), adds a LaunchAgent at ~/Library/LaunchAgents/com.brrr.agent.plist. brrr --uninstall removes the agent and the sudoers rule, and asks for your password again.

Boosting turns off Low Power Mode for the power source you are on (battery or charger) and, on MacBook Pros that have High Power Mode, turns that on. If neither applies, the Mac is already at full power and brrr has nothing to change.

Omarchy

omarchy plugin add https://github.com/valvesky/brrr.git --enable

That is the whole install. The plugin ships prebuilt static binaries for x86_64 and aarch64, so there is nothing to build and no package to install. The widget’s icons come from the bar’s Nerd Font.

On any other architecture, run make in ~/.config/omarchy/plugins/raw.brrr (it needs Rust), then restart the Omarchy shell. The plugin uses that build when no prebuilt binary fits.

The plugin’s background service runs one brrr for as long as the shell runs, however many bars show the widget. The widget shows whether automatic boost is on, the status, and the watched commands. Its switch is saved in your configuration and kept across restarts. Plugin updates replace and restart brrr.

Under the shell, brrr runs with --supervised: it prints its state as JSON lines on stdout and exits when that stdin pipe closes, so it never outlives the shell. The service writes the latest state to $XDG_RUNTIME_DIR/brrr-status.json for the widgets. Another bar can read the same lines.

Remove it with omarchy plugin remove raw.brrr. brrr stops with the plugin. Your configuration file is separate and stays.

If you installed an early Omapower with setup.sh, the plugin retires that old systemd user service once, on first start. It only removes ~/.config/systemd/user/omapower.service when that unit’s ExecStart is the binary under ~/.local/share/omapower, and it deletes that directory. A unit you wrote yourself is left alone. The command list is kept.

From source

brrr is one Rust package and needs Rust 1.89 or newer. Building on a system produces that system’s binary:

cargo build --release      # target/release/brrr

make test runs the Rust unit tests, the command-line and JSON compatibility tests, the widget’s JavaScript tests, and, on Linux, the isolated D-Bus integration tests (including a headless Quickshell run of the plugin). Those need jq, Node.js, dbus-run-session, a C compiler, Quickshell, and Python with PyGObject. On Windows and macOS, cargo test runs the unit tests.
