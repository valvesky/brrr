Adding apps

brrr does not care what a program is for. It cares what the process is called. A compiler, a game, a zipper, and a video export are the same kind of entry: a process name.

From the icon

Every desktop has the same pieces: a switch for automatic boost, the list of watched names, a way to add one, and a way to open the configuration file. The wording follows the platform.

WhereAddRemove
Windows notification area Watched commands → Add command…. The dialog title is “Add Command” and the field says “Process name (without .exe):”. Click the name and confirm “Stop watching …?”.
Linux tray Watched Commands → Add Command…. Uses zenity, kdialog, or qarma. If none of those is installed, it opens the config file instead. Open the name and choose Stop Watching.
macOS menu bar Watched Commands → Add Command…. The prompt says “Enter the process name to watch, such as cargo or swiftc.” Click the name and confirm “Stop watching …?”.
Omarchy widget The + button (tooltip “Add command”), then the process name (placeholder “Process name”), then Add. The × on that name (tooltip “Remove command”).

A name that is running is marked in the list (a check mark on Windows and macOS, “(running)” on Linux). The switch is labelled Automatic boost on Windows and Automatic Boost on Linux and macOS. Turning it off is the same as brrr --disable. While the configuration file is invalid, the switch and the add action are disabled until you fix the file.

From the terminal

brrr --add NAME
brrr --remove NAME
brrr --disable    # or --enable

On Omarchy the binary in the plugin is ~/.config/omarchy/plugins/raw.brrr/bin/brrr. The running brrr notices the edit immediately. You do not restart it.

Usage: brrr [--tray | --headless] [--poll]
       brrr --supervised [--poll]
       brrr --add NAME | --remove NAME | --enable | --disable
       brrr --install | --uninstall

  --tray        show the status icon (the default on Windows and macOS)
  --headless    run without an icon (the default on Linux, for systemd)
  --supervised  report state as JSON lines on stdout; exit when stdin closes
  --poll        scan processes on a timer instead of using kernel events
  --install     start at login (and, on macOS, allow the power mode switch)
  --uninstall   undo --install

--poll only changes process detection on Linux. Windows and macOS already scan on a timer.

What a name is allowed to be

A name is the process name, not a path and not the command line. It must be 1 to 15 bytes, with no slashes, newlines, or NUL bytes. The limit is bytes, not characters: swift-frontend is 15 bytes and is accepted; eight é characters are 16 bytes and are rejected. The same limit is used on every system so one config file stays portable. It matches Linux comm, which the kernel stores in 15 bytes.

  • Linux. The name must match the process’s comm exactly, including case. That is the name ps -o comm= prints. A longer program name is already truncated to 15 bytes by the kernel, so you watch the truncated form.
  • macOS. The name must match the process name or its comm exactly, including case. brrr counts your own processes (the real or effective user).
  • Windows. Use the program’s file name without .exe. Matching ignores case, so msbuild matches MSBuild.exe. Putting .exe in the config does not match: brrr strips one .exe suffix from the live process and compares that to the name you saved. The Windows dialog says this outright.

A process name longer than 15 bytes cannot be added. brrr will not watch it under a shortened guess. Pick the name the operating system actually reports, and only if it fits.

brrr sees programs however you started them: a shortcut, a script, an IDE, make && zig build. On Linux it also sees processes you started as another user (such as root through sudo) when they still carry your login uid. Other people’s processes and system services do not match. On Windows it counts programs in your own logon session, including ones you started as administrator.

What is already in the list

When the configuration file is missing, brrr watches these compilers. The moment a file exists, even an empty list, your list is kept and the defaults are not filled back in.

Every system:

  • rustc
  • cargo
  • gcc
  • g++
  • cc
  • c++
  • cc1
  • cc1plus
  • clang
  • clang++
  • zig
  • go
  • javac
  • swiftc
  • swift-frontend
  • gfortran
  • flang
  • nvcc
  • ghc

cc1 and cc1plus are GCC’s own workers, so a compile stays covered even when the driver process has a different name.

Also on Windows: cl and msbuild. Also on macOS: xcodebuild and swift-build.

Nothing else is watched until you add it. A game or an exporter is not in this list unless its process name happens to be one of these, which it will not. Add that name yourself.
